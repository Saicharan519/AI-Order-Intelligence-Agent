## Parsing quirks handled by the loader

- Quoting is inconsistent: some fields are quoted, others not, even within one file.
- The reviews file has 104,720 lines for 99,224 records: review comments contain line breaks inside quoted fields.
- The translation file starts with a UTF-8 byte-order mark and uses Windows (CRLF) line endings.
- Empty fields are empty strings; the loader converts them to NULL.
- Zip-code prefixes have leading zeros (`"01037"`), so they are stored as text.

For these reasons the loader parses with Python's `csv` module and streams rows to PostgreSQL with `COPY`, rather than using server-side `COPY ... CSV` directly.

## Reproduced figures

Every dataset figure in PRD sections 5.2 and 5.3 was re-computed with our own SQL on the raw tables: see [data_profile.md](data_profile.md) (generated by `scripts/check_counts.py`). Result on 2026-10-15: all required checks pass and all PRD figures match after one correction:

- **Small sellers:** the PRD said 57 sellers show a 100% late rate with 3 or fewer orders. Under the PRD's own definition of late (date comparison) the figure is **51**; 57 is what the timestamp comparison gives. Corrected in PRD v1.2 and technical design v1.2.

Additional facts found (not in the PRD):

- No orphans: every item, payment, and review references an existing order; every order a customer; every item a product and a seller.
- 775 orders have no items (mostly canceled or unavailable). They contribute 0 item revenue.
- 1 order has no payment row.
- `order_estimated_delivery_date` is midnight in every row, confirming that it is a date stored as a timestamp.
- Reviews created before the recorded delivery date: 5.3% of reviews of delivered orders (PRD: "about 5%").
